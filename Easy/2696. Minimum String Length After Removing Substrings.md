# 2696. Minimum String Length After Removing Substrings
Problem : [HERE](https://leetcode.com/problems/minimum-string-length-after-removing-substrings/description/)

>[!TIP]
>LeetCode 2696 "Minimum String Length After Removing Substrings" 題目要求我們不斷移除字符串中出現的特定子字符串，直到無法再移除為止，然後返回最終剩下的字符串長度。
>
>### 題目理解
>- 我們給定一個字符串 `s`，每次可以從中移除子字符串 `"AB"` 或 `"CD"`，當無法再移除這些子字符串時，返回最終字符串的長度。
>- 重複移除直到找不到 `"AB"` 或 `"CD"`。
>
>### 解題思路
>1. **暴力法**：
>   - 最直接的解法是模擬整個過程，不斷搜索字符串中出現的 `"AB"` 和 `"CD"`，找到一對就移除，直到無法再找到這些子字符串為止。
>   - 這種方法的時間複雜度可能比較高，因為每次移除一對後，還需要再次從頭搜索。
>
>2. **棧 (Stack) 解法**：
>   - 由於每次遇到 `"AB"` 或 `"CD"` 就移除，這可以被視作是一種平衡的過程，我們可以用棧來模擬這個過程。
>   - 當遍歷字符串時，我們將字符逐個壓入棧中，並在棧頂遇到 `"A"` 且當前字符為 `"B"` 或棧頂是 `"C"` 且當前字符是 `"D"` 時，移除它們（相當於模擬移除這些子字符串）。
>   - 最終棧中剩下的就是無法被移除的字符，棧的長度就是最終的字符串長度。
>
>### 具體步驟
>1. 初始化一個空棧。
>2. 遍歷字符串：
>   - 如果當前字符可以與棧頂形成 `"AB"` 或 `"CD"`，則移除棧頂元素（相當於移除這對子字符串）。
>   - 否則，將當前字符壓入棧中。
>3. 遍歷結束後，棧的大小即為無法移除後的最小字符串長度。
>
>### 解釋
>- **棧的使用**：我們使用棧來模擬逐字符判斷和移除的過程。當棧頂的字符與當前字符能夠形成 `"AB"` 或 `"CD"` 時，這對字符被移除；否則，我們將當前字符壓入棧中。
>- **最終結果**：遍歷完成後，棧中存儲的就是剩餘無法被移除的字符。棧的大小即為最終的字符串長度。
>
>### 時間複雜度
>- **O(n)**：每個字符最多只會被壓入棧一次或被彈出一次，因此時間複雜度是線性的，與字符串長度 `n` 成正比。
>
>### 空間複雜度
>- **O(n)**：最壞情況下，棧中可能存儲所有字符，因此空間複雜度是 O(n)。
>
>### 例子
>假設輸入字符串為 `"ABCD"`：
>- 首先，我們遍歷 `"A"`，壓入棧中，棧內容變為 `['A']`。
>- 遍歷 `"B"`，此時棧頂是 `"A"`，而當前字符是 `"B"`，可以形成 `"AB"`，所以我們將棧頂 `"A"` 移除。此時棧為空。
>- 接著遍歷 `"C"`，壓入棧中，棧內容變為 `['C']`。
>- 最後遍歷 `"D"`，此時棧頂是 `"C"`，而當前字符是 `"D"`，可以形成 `"CD"`，所以我們將棧頂 `"C"` 移除。此時棧為空。
>
>最終棧為空，因此最小字符串長度為 `0`。
>
>### 總結
>這道題的關鍵在於使用棧來高效模擬消除 `"AB"` 和 `"CD"` 的過程，通過每次匹配和移除字符對來最終確定最小的字符串長度。

>[!TIP]
>在 C++ 中，`stack` 和 `vector` 是兩種不同的容器類型，它們有各自的特點和用途。以下是它們之間的主要區別：
>
>### 1. **基礎結構**
>   - **`stack`**：
>     - `stack` 是一種**後進先出（LIFO, Last In First Out）**的數據結構。
>     - 它只允許從**頂端插入和刪除元素**。
>     - 底層實現通常是基於其他容器，如 `deque` 或 `vector`，但它只提供有限的操作來保持後進先出的特性。
>   - **`vector`**：
>     - `vector` 是一種**動態數組**，可以在任意位置進行插入、刪除和訪問。
>     - 支持**隨機訪問**，即可以通過索引直接訪問任意位置的元素。
>     - 它是一個通用的容器，允許進行更多操作，如插入、刪除、遍歷等。
>
>### 2. **可用操作**
>   - **`stack`**：
>     - `push()`：將元素插入棧頂。
>     - `pop()`：移除棧頂元素。
>     - `top()`：查看棧頂元素（但不移除）。
>     - `empty()`：檢查棧是否為空。
>     - `size()`：返回棧中的元素個數。
>     - 不能使用索引操作訪問棧中的其他元素。
>   - **`vector`**：
>     - `push_back()`：將元素插入到數組尾部。
>     - `pop_back()`：刪除數組尾部的元素。
>     - `operator[]` 或 `at()`：通過索引訪問元素。
>     - `insert()`：插入元素到任意位置。
>     - `erase()`：刪除任意位置的元素。
>     - `size()`：返回當前元素個數。
>     - `capacity()`：返回容器的容量。
>     - `resize()`：調整容器的大小。
>     - `clear()`：清空容器。
>     - 支持遍歷和隨機訪問。
>
>### 3. **用法場景**
>   - **`stack`**：
>     - 適合處理**後進先出（LIFO）**的問題，如處理括號匹配、函數調用棧、深度優先搜索等。
>     - 當你只需要操作棧頂的元素時，使用 `stack` 是最方便的，因為它限制了不必要的操作。
>   - **`vector`**：
>     - 適合用於**動態數據存儲**，需要頻繁的插入、刪除和隨機訪問時。
>     - 可以用來表示靜態和動態長度的數組，尤其是當你需要頻繁操作尾部元素時，`vector` 是高效的選擇。>
>
>### 4. **性能**
>   - **`stack`**：
>     - 因為 `stack` 只允許操作棧頂的元素，所有操作的時間複雜度通常是**O(1)**，即常數時間操作。
>     - 但是它不允許訪問棧底或中間元素，這樣的限制在某些場景下反而提高了性能。
>   - **`vector`**：
>     - `vector` 支持隨機訪問，訪問操作的時間複雜度是**O(1)**。
>     - 插入或刪除尾部元素的時間複雜度是**O(1)**，但是如果在中間插入或刪除，時間複雜度是**O(n)**。
>     - 當 `vector` 容量不足時會自動擴容，擴容操作的時間複雜度是攤銷 O(1) 的，但會帶來一些性能開銷。
>
>### 5. **靈活性**
>   - **`stack`**：
>     - `stack` 是一個較為簡單的數據結構，操作受到限制，只能處理棧頂的元素，因此它的應用場景是比較專門的。
>   - **`vector`**：
>     - `vector` 是一個非常靈活的容器，提供了更多的操作，可以在任意位置進行插入、刪除和訪問，適用於更廣泛的場景。
>
>### 總結
>- **`stack`**：適合用於處理後進先出的場景，如括號匹配、DFS 等，限制了操作範圍，提升了效率。
>- **`vector`**：是一個靈活的容器，支持隨機訪問和更複雜的操作，適合需要頻繁增刪查改的情況。
>
>根據具體需求選擇適合的容器能夠提高程式的效率和可讀性。





```CPP
class Solution {
public:
    int minLength(string s) {
        stack<char>stk;
        for(char c : s){
            if(!stk.empty() && ((stk.top() == 'A' && c == 'B') || (stk.top() == 'C' && c == 'D'))){
                stk.pop();
            }
            else{
                stk.push(c);
            }
        }
        return stk.size();
    }
};
```
