# 3217. Delete Nodes From Linked List Present in Array

Problem : [HERE](https://leetcode.com/problems/delete-nodes-from-linked-list-present-in-array/description/)

>[!TIP]
>先找出新的起始點，然後開始往後
>
>判斷有沒有在nums裡面的時候要改成set，不然會time limit
>
>你遇到的問題是因為 `std::find` 和 `std::set::count` 這兩種操作的時間複雜度不同，導致在資料量較大的時候性能差異明顯。
>
>### 1. `std::find` 的時間複雜度
>`std::find` 的工作方式是在容器中從頭到尾依次查找目標值，直到找到或走到容器的結尾。因此，它的時間複雜度是 **O(n)**，其中 `n` 是容器的大小。也就是說，當`vector`中的元素越多，`std::find`需要的時間就越長，尤其當目標元素位於靠近容器末尾時，時間代價會更高。
>
>### 2. `std::set::count` 的時間複雜度
>`std::set` 是一個平衡的二元搜索樹（例如紅黑樹），插入和查找的時間複雜度都是 **O(log n)**。`std::set::count` 是用來檢查某個元素是否存在於`set`中，它的工作原理基於二元搜索樹，因此可以在對數時間內完成查找。
>
>### 差異總結：
>- `std::find` 在 `std::vector` 上是線性查找，時間複雜度是 **O(n)**，所以當數據量變大時，可能會超過時間限制。
>- `std::set` 使用平衡樹來組織資料，因此`count`的時間複雜度是 **O(log n)**，效率比線性查找高得多。
>
>這也是為什麼當數據量較大時，`std::set::count` 不會出現時間限制問題，而 `std::find` 在 `std::vector` 中可能會有性能瓶頸。>
>
>### 解決方案：
>如果你的查找操作頻繁且資料量較大，考慮將 `std::vector` 替換為 `std::set` 或其他具有快速查找特性的容器（如 `std::unordered_set`，其查找時間複雜度接近 **O(1)**）。這樣可以顯著提升查找效率。

```CPP
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode() : val(0), next(nullptr) {}
 *     ListNode(int x) : val(x), next(nullptr) {}
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    ListNode* modifiedList(vector<int>& nums, ListNode* head) {
        ListNode* current = head;
        set<int> numsSet(nums.begin() , nums.end());
        while(current){
            if(numsSet.count(current -> val)){
                current = current -> next;
            }
            else break;
        }
        ListNode* ans = current;
        while(current && current -> next){
            if(numsSet.count(current -> next -> val)){
                current -> next = current -> next ->next;
            }
            else current = current -> next;
        }
    return ans;
    }
};
```
