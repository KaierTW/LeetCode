# 146. LRU Cache
Problem : [HERE](https://leetcode.com/problems/lru-cache/description/)

>[!TIP]
>
>這題是 LeetCode #146 - **LRU Cache**，屬於常見的系統設計題，重點在於實作一個具有「最近最少使用（Least Recently Used）」特性的快取機制，**要求 O(1) 的 get 和 put 操作時間複雜度**。
>
>---
>
>## ✅ 實作方式（C++）
>
>使用兩個資料結構：
>
>1. `unordered_map<int, list<pair<int, int>>::iterator>`
>
>   * Key: 快取的 key
>   * Value: 指向雙向鏈表中該節點的 iterator
>
>2. `list<pair<int, int>>`
>
>   * 雙向鏈表，紀錄最近使用的順序（最前面是最近使用的）
>
>### 💡 為什麼用 `list`？
>
>* `list` 可以在 **O(1)** 時間內移除、插入任意位置（搭配 iterator）
>
>---
>
>### 🧠 核心操作：
>
>* `get(key)`：
>
>  * 如果 key 存在：把對應節點移到 list 前面，並回傳 value
>  * 否則回傳 -1
>
>* `put(key, value)`：
>
>  * 如果 key 已存在：更新 value 並移動到最前面
>  * 如果 key 不存在：
>
>    * 若快取容量滿了，刪除 list 最後面（最久未用）的元素
>    * 插入新元素到 list 最前面，更新 map
>
>---
>
>### ✅ C++ 程式碼：
>
>```cpp
>#include <unordered_map>
>#include <list>
>using namespace std;
>
>class LRUCache {
>private:
>    int capacity;
>    list<pair<int, int>> cache;  // key, value
>    unordered_map<int, list<pair<int, int>>::iterator> map;
>
>public:
>    LRUCache(int capacity) {
>        this->capacity = capacity;
>    }
>
>    int get(int key) {
>        if (map.find(key) == map.end()) {
>            return -1;
>        }
>
>        // 移動到最前面
>        auto it = map[key];
>        int value = it->second;
>
>        cache.erase(it);
>        cache.push_front({key, value});
>        map[key] = cache.begin();
>
>        return value;
>    }
>
>    void put(int key, int value) {
>        if (map.find(key) != map.end()) {
>            // 刪除原本的節點
>            cache.erase(map[key]);
>        } else if (cache.size() == capacity) {
>            // 移除最久未使用的
>            auto last = cache.back();
>            map.erase(last.first);
>            cache.pop_back();
>        }
>
>        // 插入新節點到前面
>        cache.push_front({key, value});
>        map[key] = cache.begin();
>    }
>};
>```
>
>---
>
>## ✅ 時間複雜度分析
>
>| 操作                | 時間複雜度 |
>| ----------------- | ----- |
>| `get(key)`        | O(1)  |
>| `put(key, value)` | O(1)  |
>
> 因為所有操作都透過 `unordered_map` 和 `list` 完成，使用 iterator 進行刪除與移動都為常數時間。

>## 🧩 一、`list` vs `vector` 差異總覽
>
>| 特性            | `std::list`（linked list） | `std::vector`（array）  |
>| ------------- | ------------------------ | --------------------- |
>| 記憶體布局         | ❌ 不連續（每節點分散在各處）          | ✅ 連續記憶體               |
>| 存取方式          | ❌ 無法隨機存取（不能用 `[]`）       | ✅ 可隨機存取 `vec[i]` O(1) |
>| 插入/刪除（中間位置）   | ✅ O(1)，只改指標              | ❌ O(N)，會搬移後面元素        |
>| 插入/刪除（尾端）     | ✅ O(1)                   | ✅ Amortized O(1)      |
>| 遍歷效能          | ❌ 較慢（cache 不友善）          | ✅ 較快（cache 友善）        |
>| iterator 是否穩定 | ✅ 大部分穩定（除非刪掉那一個）         | ❌ 可能失效（例如擴容或刪除）       |
>| 適用場景          | LRU Cache, 頻繁插入/刪除       | 高速查找/遍歷、大量資料處理        |
>
>---
>
>## 🔁 二、`iterator` 是什麼？
>
>* STL 容器的 iterator = 一種 **指向容器元素的 smart pointer**
>* 用法類似指標：
>
>  ```cpp
>  *it       // 解參照，取出值
>  it->first // 若是 pair 型別，可以用 -> 存取
>  ++it      // 移到下一個元素
>  ```
>
>---
>
>## 💥 三、iterator 與操作的影響
>
>| 操作             | `std::list` 的 iterator 影響 | `std::vector` 的 iterator 影響 |
>| -------------- | ------------------------- | --------------------------- |
>| `erase(it)`    | 只有該 iterator 失效           | 該位置與之後的 iterator 全失效        |
>| `push_front()` | 原本的 iterator 不受影響         | N/A（vector 沒有此操作）           |
>| `push_back()`  | iterator 不變               | 若擴容，所有 iterator 全失效         |
>
>---
>
>## 🧠 四、為什麼 `list<pair<int,int>>::iterator` 要這樣寫？
>
>* `list<pair<int,int>>` 是容器類型，裡面每個元素是 `pair<int,int>`
>* `::iterator` 表示這個容器中「元素的位置型別」
>* 因此：
>
>  ```cpp
>  list<pair<int, int>>::iterator it = cache.begin();
>  ```
>
>  表示 `it` 是指向 `cache` 中某個 `{key, value}` 的位置
>
>---
>
>## 📌 五、應用在 LRU Cache
>
>```cpp
>unordered_map<int, list<pair<int,int>>::iterator> map;
>```
>
>* 用 `unordered_map` 快速找到某個 key 的位置
>* 用 `list` 維持使用順序（越前面代表越常用）
>* `iterator` 幫助我們 O(1) 移除/更新該節點
>
>---
>
>## ✅ 總結一句話：
>
> 1. `std::vector` 是快取友善的連續陣列，適合大量查找與遍歷；
> 2. `std::list` 是非連續記憶體的雙向 linked list，適合頻繁插入與刪除。
> 3. STL 的 `iterator` 像是 smart pointer，可用來快速操作容器內元素，避免 O(N) 查找。
>
>---
>

```CPP
class LRUCache {
private:
    list<pair<int, int>> list_cache;; // {Key, value};
    unordered_map<int, list<pair<int, int>>::iterator> uom_map;
    int cacheCapacity;
public:
    LRUCache(int capacity) {
        cacheCapacity = capacity;
    }
    
    int get(int key) {
        if(uom_map.find(key) != uom_map.end()){
            auto it = uom_map[key];
            int value = it -> second;
            list_cache.erase(it);
            list_cache.push_front({key, value});
            uom_map[key] = list_cache.begin();
            return value;
        }
        else return -1;
    }
    
    void put(int key, int value) {
        // Find key in map
        if(uom_map.find(key) != uom_map.end()){
            list_cache.erase(uom_map[key]);
        }
        else{
            // If cache is full
            if(list_cache.size() == cacheCapacity){
                auto last = list_cache.back();
                uom_map.erase(last.first);
                list_cache.pop_back();
            }
        }    
        list_cache.push_front({key, value});
        uom_map[key] = list_cache.begin();
    }
};

/**
 * Your LRUCache object will be instantiated and called as such:
 * LRUCache* obj = new LRUCache(capacity);
 * int param_1 = obj->get(key);
 * obj->put(key,value);
 */
```
