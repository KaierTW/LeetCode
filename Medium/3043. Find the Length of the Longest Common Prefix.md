# 3043. Find the Length of the Longest Common Prefix
Problem : [HERE](https://leetcode.com/problems/find-the-length-of-the-longest-common-prefix/description/)

>[!TIP]
>使用 **哈希表** 的概念來解決這類公共前綴問題是個好主意。哈希表可以幫助我們快速查找和比較數字的前綴，並大幅減少不必要的重複計算。以下是一些使用哈希表的可能思路和優化策略。
>
>### 哈希表優化思路：
>1. **將數字轉為字符串並存儲其前綴**：
>   - 可以將 `arr1` 中的每個數字轉換成字符串，並存入哈希表，鍵是前綴，值是這個前綴的長度。
>   - 對於 `arr2` 中的每個數字，我們檢查它的前綴是否存在於哈希表中，並記錄最長的公共前綴。
>
>2. **利用哈希表快速檢索前綴**：
>   - 我們可以將數字的所有前綴存入哈希表中，這樣當我們遍歷另一個數組時，可以快速檢索是否有匹配的前綴。
>
>### 解法思路：
>1. 先處理 `arr1`，對每個數字生成所有可能的前綴，並將其存入哈希表。
>2. 對 `arr2` 中的每個數字，從最長的前綴開始，逐步查找是否存在匹配的前綴。
>3. 最後，返回最長的匹配前綴長度。
>
>### 解釋：
>1. **生成前綴**：對於 `arr1` 中的每個數字，將其轉為字符串，並逐步生成從1位到整個數字的所有前綴，存入哈希表。
>2. **查找匹配前綴**：對於 `arr2` 中的每個數字，從最短的前綴開始逐步檢查哈希表中是否有匹配的前綴。只要找到匹配，就可以更新最大前綴長度。
>3. **最終結果**：返回最大公共前綴的長度。
>
>### 時間複雜度：
>- **時間複雜度**: 生成和查找前綴的時間複雜度大約是 O(n * L1 + m * L2)，其中 n 和 m 是兩個數組的長度，L1 和 L2 是數字轉換為字符串後的長度。
>- **空間複雜度**: 哈希表的空間需求是 O(n * L1)，因為需要存儲所有前綴。
>
>這樣的解法利用哈希表快速查找和匹配前綴，可以有效降低時間複雜度，避免雙重遍歷導致的超時問題。這個解法應該能解決你遇到的時間限制問題。
>
>當我們使用哈希表來解決這類問題時，主要的目的是利用哈希表 **快速查找和存儲數據** 的特性，來優化對公共前綴的查找過程。這樣可以減少不必要的比較，從而提高運行效率。
>
>### 1. 哈希表的基本原理
>- **哈希表**（Hash Table）是一種 **鍵值對**（key-value pair）結構，通過 **哈希函數** 將一個鍵（如字串、數字）映射到一個特定的位置（通常是陣列中的索引），以實現快速查找和存儲操作。
>- 對於查找和插入操作，哈希表通常可以在 **O(1)** 的時間內完成，這比線性掃描 O(n) 更高效。
>
>### 2. 如何在公共前綴問題中使用哈希表？
>這裡的問題是要在兩個數組中查找數字之間的公共前綴。如果我們對所有數字都進行逐一比較，時間複雜度會是 O(n * m)，這對於大數據量來說效率不高。而哈希表允許我們通過 **快速查找** 減少比較的次數。
>
>### 核心思路：
>- **第一步**：對於數組 `arr1` 中的每個數字，我們可以生成它的所有可能前綴，並將這些前綴存入哈希表中。
>  - 例如，對於數字 `1000`，它的所有前綴是：`1`、`10`、`100` 和 `1000`。這些前綴會存入哈希表，鍵是這些前綴的字符串，值是它們的長度。
> 
>- **第二步**：當處理數組 `arr2` 中的數字時，我們會逐個檢查它們的前綴是否已經存在於哈希表中。
>  - 如果存在，說明這個前綴與 `arr1` 中某個數字有共同的前綴，並且我們可以立即知道這個前綴的長度。
>  - 我們只需要更新找到的最大前綴長度即可，而不需要再次遍歷 `arr1` 中的所有數字來進行逐一比較。
>
>### 具體運作過程：
>1. **存入前綴**：對於 `arr1` 中的每個數字，生成它的所有前綴並存入哈希表：
>   - 比如對於 `arr1 = [100, 101]`，將 `100` 和 `101` 轉為字符串，然後生成所有前綴：
>     - `100` 的前綴是：`1`, `10`, `100`
>     - `101` 的前綴是：`1`, `10`, `101`
>   - 將這些前綴作為鍵存入哈希表，並記錄對應的前綴長度。例如，`哈希表["1"] = 1`，`哈希表["10"] = 2`，`哈希表["100"] = 3`。
>
>2. **查找匹配前綴**：當我們處理 `arr2` 中的數字時，例如對於 `arr2 = [102, 200]`：
>   - 將 `102` 轉換為字符串，並逐個檢查它的前綴是否存在於哈希表中：
>     - `102` 的前綴是：`1`, `10`, `102`
>     - 查找哈希表，發現 `1` 和 `10` 是 `arr1` 的某些數字的前綴，並且對應的最大前綴長度為 `2`，所以更新結果。
>   - 再處理 `200` 時，發現它的前綴 `2` 不存在於哈希表中，因此它與 `arr1` 中的數字沒有公共前綴。
>
>### 為什麼哈希表能優化性能？
>哈希表能夠以 **常數時間** O(1) 進行查找，而傳統的逐一比較需要 O(n)。當 `arr1` 或 `arr2` 數組長度較大時，哈希表可以顯著減少查找次數。具體來說：
>- **插入操作**：將 `arr1` 中數字的前綴插入到哈希表的時間複雜度為 O(n * L1)，其中 `L1` 是數字轉為字符串後的最大長度。
>- **查找操作**：在 `arr2` 中查找前綴的時間複雜度為 O(m * L2)，其中 `L2` 是數字轉為字符串後的最大長度。
>- 總的來說，這樣的解法比雙層遍歷（O(n * m * min(L1, L2)）要更高效。
>
>### 小結：
>使用哈希表的關鍵優勢在於 **快速查找**，通過提前將 `arr1` 的前綴存入哈希表，當遍歷 `arr2` 時，只需要常數時間查找匹配前綴，這樣可以有效降低整體時間複雜度。
>
>這種方法在較大數組下能顯著提升效率，特別是在處理前綴問題或其他類似的查找問題時。
>


```CPP
class Solution {
public:
    int longestCommonPrefix(vector<int>& arr1, vector<int>& arr2) {
        unordered_map<string , int> prefixMap;
        int ans = 0;
        for(int arr : arr1){
            string string_arr = to_string(arr);
            for(int i = 1 ; i <= string_arr.size() ; i++){
                prefixMap[string_arr.substr(0 , i)] = i;
            }
        }
        for(int arr : arr2){
            string string_arr = to_string(arr);
            for(int i = 1 ; i <= string_arr.size() ; i++){
                string prefix = string_arr.substr(0 , i);
                if(prefixMap.find(prefix) != prefixMap.end()){
                    ans = max(ans , prefixMap[prefix]);
                }
            }
        }
        return ans;
    }
};
```
